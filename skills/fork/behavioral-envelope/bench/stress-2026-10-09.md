# Stress test rerun, 2026-10-09

Same eight requests and answer keys as [stress-2026-10-08.md](stress-2026-10-08.md), run again after `SKILL.md` was rewritten so every section ends on a checkable **Done when** line and prohibitions were restated as target behavior. Each request was planned twice by a fresh agent following sections 1 to 8, blind to the keys and to the other run. `score-stress.py <dir>` scores a folder of `<scenario>-A.md` and `<scenario>-B.md` envelopes.

## What changed and what it shows

1. **Every run produced an envelope the gate accepts.** All 16 pass G2 (Packs line filled, every Live row with severity, mechanism, enforcement point and proof). Every agent also reported each section's Done when as met and checked several by script (one answer per item, one mechanism per Live ID). The rewrite turned "answer every item" from an instruction into a condition agents verify.
2. **Recall held at 100%.**
3. **Agreement fell on the earlier measure and held on pack items.** Overlap of all Live IDs is 82%, against 88% on 2026-10-08. Part of the drop is naming: several runs put their extra items in the Live table, and each run names them differently (`X-01`, `EX-1`), so they never match. On pack items alone it is 89%. Whether the earlier run's 88% included extra items was not recorded, so the two numbers are only roughly comparable.
4. **The remaining disagreement is packs added by judgment.** Within packs both runs selected, agreement is 93%. Seat billing (81% vs 94%) and column rename (85% vs 90%) differ mostly by packs one run added. Two fixes to `detect-packs.sh` followed, each with a fixture in `test-detect.sh`:
   - `infra-config` now matches "deploys", "zero downtime", "secrets" and "API keys" (the column-rename request says "deploys", which the old pattern missed);
   - `money` now implies `personal-data` (billing and trading carry customer identity and payment details).
5. **Live counts went up** (for example 107 and 90 on email sequences, against 70 and 68). The rewritten section 3 asks for an answer for every item and a check of it, so fewer items were left implicit. Severity keeps it workable: Critical items run from 0 (the color change) to 39 per feature and are built first.

## Limits

Two runs per scenario, one model family, no codebase. The second pass (section 5) was done by the same agent after setting its answers aside, because these agents could not spawn subagents, so it is less independent than the skill asks for. The two script fixes are not yet measured by a third run.
