# Stress test, 2026-10-08

Eight plain-language requests (`scenarios/`), each planned twice by a fresh agent following `SKILL.md` sections 1 to 8, blind to the answer keys. The keys (`scenarios/answer-keys.json`) were written before any run: the concerns a senior engineer would require, the mechanisms that should appear, and items that must not be Live.

## Results

| Scenario | Recall run A | Recall run B | Run agreement | Live A / B | Key mechanisms found (A, B) |
|---|---|---|---|---|---|
| AI follow-up email sequences | 100% | 100% | 92% | 70 / 68 | all, all |
| Two-way HubSpot contact sync | 100% | 100% | 91% | 65 / 61 | all, all |
| Quant order placement | 100% | 100% | 89% | 45 / 42 | all, all |
| Button color change | 100% | 100% | 91% | 11 / 10 | all, all |
| Customer-docs knowledge base (RAG) | 100% | 100% | 91% | 68 / 66 | all, all |
| Seat billing with Stripe | 100% | 100% | 73% | 43 / 59 | all, all |
| Column rename on 40M rows | 100% | 100% | 91% | 22 / 20 | all, all |
| Password reset | 100% | 100% | 83% | 52 / 45 | all, all |

Recall is the share of key items marked Live. Agreement is the overlap of the two runs' Live sets (intersection over union). No run marked a must-not item Live. Every build plan put shared mechanisms first.

## What the numbers hid, and what changed

1. **Disagreement came from packs added by judgment.** The script missed `api` and `data` for billing, password reset and quant, so one run added them and the other did not (billing agreement 73%). Fix: `detect-packs.sh` now adds implied packs (money implies data and api, inbound events imply api and data, and so on) and knows cadence words ("every minute"). Billing re-run twice after the fix: recall 100% both, agreement 94%, identical Critical lists.
2. **Live was too flat.** 40 to 70 Live items per feature with no ranking put a double charge next to a loading state. Fix: every Live item now has a severity (Critical, High, Normal); Critical items need structural enforcement and a failure-injecting proof, and are built first.
3. **The keys only covered pack items**, so 100% recall shows the answer-every-item floor works, not that the packs are complete. The stronger signal was section 4: both runs of a scenario independently added the same concerns that no pack held. Those became pack items: JOB-09 calendar rules, INT-09 two-way sync loops, MON-08 orders in flight, VIS-11 values search cannot see, ID-09 single-use tokens, RET-09 real citations, RET-10 customer-supplied URLs.

## Limits

Two runs per scenario, one model family, no codebase (failure paths name planned components). Rerun the full set after any change to the packs, the script or `SKILL.md`, and add a scenario for every escaped bug.
